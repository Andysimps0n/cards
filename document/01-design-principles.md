# 카드뉴스 디자인 원칙 (Cursor Agent 전달용) — 「크레파스 모험일지」

> 작성: Alyssa · 기준일 2026-10-03 · 원본 디자인 시스템 v0.1 (`document/02-design-system-full.md`, 12절까지 포함)
> 제작 방식: HTML/CSS로 카드를 만들고 headless Chrome으로 PNG 캡처
> 표기 규칙: **확정** = 사용자와 정했거나 템플릿/실제 게시물에 반영된 값 · **제안** = 제안만 하고 확정은 안 된 값 · **미정** = 아직 안 정함

## 0. 한눈에 보기

- 캔버스 **1080 × 1350px (4:5)**, 배경 크림 도화지 `#FFF9F0`, 글자 잉크 `#3D3654`
- 콘셉트: **파스텔 크레파스로 그린 모험 일지·보물지도** (퀘스트, 보물 X 표시, 점선 루트)
- **크레파스 질감은 장식에만 넣고, 글자는 항상 선명하게** (가장 중요한 원칙)
- 표준 구조(용어 시리즈): **9장** = 커버 → 문제 제기 → 용어 ×5 → 한눈에 비교 → 엔딩
- **사진은 없음**: 모든 시각 요소는 CSS/SVG로 그린 손그림 장식과 미니 목업
- 그대로 쓸 수 있는 템플릿과 렌더 스크립트가 ``에 있음 (7절 참고)

## 1. 계정·톤 & 타깃

### 계정 (확정)
- 한국어 **공부 기록 계정**. 개발 지식을 재미있게 풀어서 나눔
- 목적
  1. 개발에 관심 있는 사람들에게 도움이 되는 정보 공유 (웹개발 스킬셋, 프롬프트, AI를 효율적으로 쓰는 법)
  2. 콘텐츠를 만들려고 조사하고 공부하면서 나도 더 배우기 ("자료조사하는 김에 공유")
- 포지션: **선생님이 아니라 한발 앞서 걸어보는 동료**. "제가 조사해봤는데요" 톤
- 계정 아이디: **미정** (모든 카드에 `@handle` 자리표시로 들어가 있음)
  - → **2026-10-03 확정: `@crayon.sure`** (`src/ui/Post.jsx`에서 설정, Andy가 직접 관리)
- 계정 이름 / 바이오: **미정** (바이오 예시 "개발 공부하다 알게 된 거, 재밌게 풀어드림 🧭 UI/UX · AI 도구 · 개발 일지"는 제안 단계)

### 타깃 (확정)
- 사용자 본인처럼 **개발에 관심 있는 사람**: 웹개발 입문~주니어, AI로 개발하는 사람(바이브코딩), 프롬프트와 AI 활용법을 궁금해하는 사람

### 톤 (확정)
- **친근한 존댓말(해요체)**. 반말 사용 안 함
- 가볍고 장난스러운 모험·퀘스트 비유 ("퀘스트 시작", "첫 번째 지점", "퀘스트 완료!", "보물: ○○", "같이 탐험해요")
  - → **2026-10-03 폐지.** 카드 글자와 캡션은 공부 노트 말투로 써요. 아래 "말투 규칙" 참고 (크레파스·지도풍 그림은 장식으로만 남아도 됨)
- 내 경험에서 출발하는 1인칭 ("나를 위한 UI 용어 5개", "제일 답답했던 건…")

### 기둥과 시리즈 (확정, 시리즈 = 퀘스트 타입)
| 기둥 | 시리즈 | 퀘스트 타입 | 배지 아이콘 | 코드 키(`series=`) |
|---|---|---|---|---|
| 🎨 UI/UX | 「AI한테 이렇게 말해」 (테마별 UI 용어) | 주문서 퀘스트 | 주문서 scroll | `talk` |
| 🎨 UI/UX | 「이 디자인 왜 예쁨?」 (디자인 분석) | 탐사 퀘스트 | 돋보기 | `why` |
| 🎨 UI/UX | 「만약에 UI」 (상상 UI, 가끔) | 상상 퀘스트 | 구름+별 | `whatif` |
| 🤖 AI | 「이번 주 AI」 (업데이트 뉴스) | 소식 퀘스트 | 망원경 | `weekly` |
| 🤖 AI | 「이것도 AI로 돼?」 (새 도구·가능성) | 발견 퀘스트 | 열쇠 | `cando` |
| 🧭 개발 일상 | 「개발 모험일지」 (프로젝트·외주 기록) | 메인 퀘스트 | 깃발 | `log` |
| 🧭 개발 일상 | 「주간 쓸모없는 앱」 (바이럴 챌린지) | 챌린지 퀘스트 | 주사위 | `silly` |

- 번호는 시리즈마다 따로: `QUEST #01` (두 자리). 「개발 모험일지」의 계정 소개편은 `QUEST #00`
- 콘텐츠 비율: **제안** 단계 (유용함 60% / 재미 25% / 기록 15%). 확정 아님
- 업로드 요일, 빈도: **미정**

### 「AI한테 이렇게 말해」 편성 규칙 (확정)
- **한 편 = 테마 하나**, 그 테마에 속한 UI 요소 5개를 설명
- QUEST #01: **위에 떠서 나오는 것들**, Modal · Bottom Sheet · Drawer · Toast · Tooltip (제작 완료, 아직 업로드 안 함)
- QUEST #02: **콘텐츠를 보여주는 방식** (예고 문구: "Carousel, Card, Accordion, Tab 등"). 정확한 용어 5개는 **미정** (후보: Carousel, Card, Accordion, Tab, Grid)
- #03 이후 테마: **미정** (후보: 입력하고 고르는 것들 / 기다리고 알려주는 것들 / 길 찾기)
- **페이지 구역(Header, Footer, Hero Section 등)도 '구역 편'으로 다뤄요** (2026-10-03, 예전 "페이지 뼈대 테마 영구 제외" 규칙 폐지). 예: 2탄 Header · Footer. 세부 규칙은 `04-series-rules.md`
- 계기가 된 사용자 경험: UI 이름을 몰라 AI에게 길게 설명해야 했고, 피드백을 여러 번 주고받아야 했음 → 문제 제기 장(2장)의 이야기

### 말투 규칙 (2026-10-03 확정)

카드에 들어가는 모든 글자와 캡션은 **공부 노트 말투**로 써요. 모험·퀘스트 말투는 쓰지 않아요.

#### 말투 특징
- 친근한 존댓말(해요체). 반말은 쓰지 않아요
- 선생님이 아니라 **같이 배우는 동료**가 "제가 공부해봤는데요" 하고 알게 된 걸 나누는 느낌
- 문장은 짧게. 한 문장에 한 가지만 말해요
- 단계 라벨은 짧게: 구역 편은 `구역 ①`, 용어 편은 `UI 용어 ①` (뒤에 "첫 번째 지점" 같은 꾸밈말을 붙이지 않아요)

#### 쓰지 않는 말
`퀘스트`, `QUEST 클리어`, `주문` / `주문서`, `탐험`, `모험`, `지점`, `보물`, `NEXT QUEST`

#### 바꿔 쓰는 말

| 쓰지 않는 말 | 이렇게 바꿔요 |
|---|---|
| 퀘스트 완료! | 오늘의 정리 |
| QUEST #01 클리어! | 오늘 배운 단어 5개 |
| 주문, 주문서 | 말, 프롬프트 |
| 오늘 얻은 주문 5개 | 이제 이렇게 말해요 |
| 다음 지점에서 만나요 | 다음 편에서 만나요 |
| NEXT QUEST #02 | 다음 편 |
| 팔로우하고 같이 탐험 | 팔로우하고 다음 편 보기 |
| 용어 ① 첫 번째 지점 | UI 용어 ① / 구역 ① |
| 보물: ○○ | (넣지 않음) |

#### 그림과 말투는 따로
- 크레파스 질감, 지도 모눈 배경, 점선 같은 **그림 스타일은 장식으로 남아도 돼요**
- 다만 카드 글자와 캡션에는 모험 표현을 쓰지 않아요
- 시리즈 코드 이름(`series="talk"`, `QuestTag` 같은 컴포넌트 이름)은 코드 안 이름이라 그대로 둬도 돼요. 화면에 보이는 글자만 이 규칙을 따라요

#### 계정명
- `@crayon.sure` (`src/ui/Post.jsx`에서 설정, Andy가 직접 관리해요)

## 2. 캔버스 크기, 슬라이드 수, 슬라이드별 역할 순서

### 캔버스 (확정)
- 캐러셀: **1080 × 1350px (4:5)**, 출력 PNG, `--force-device-scale-factor=1`
- 프로필 그리드는 3:4(약 1012×1350)로 잘려 보임 → 좌우 각 약 34px 잘림. 좌우 여백 88px 안에 넣으면 안전
- 릴스 커버: 1080 × 1920(9:16), 핵심 제목·배지는 가운데 1080 × 1440(3:4) 안에. 위아래 여백에는 장식만 두고 글자 금지 (규칙만 있고 **릴스 커버 템플릿은 미정/미제작**)

### 슬라이드 수 (확정)
- 「AI한테 이렇게 말해」(용어 시리즈) 표준: **9장**
- 다른 시리즈의 장 수: **미정** (미리보기 예시로 「이것도 AI로 돼?」 8장, 「개발 모험일지」 #00 6장을 페이지 번호에만 썼고 확정 아님)

### 용어 시리즈 9장 순서 (QUEST #01 기준 표준)
| 장 | 역할 | 템플릿 | QUEST #01 내용 |
|---|---|---|---|
| 01 | 커버 (퀘스트 수락) | `cover.html` | 키커 "위에 떠서 나오는 것들" / 제목 "화면 위에 뜨는 **그거**, 이름이 뭐더라?" / 부제 "AI한테 설명하다 지친 나를 위한 UI 용어 5개" / 보물: UI 이름 5개 |
| 02 | 문제 제기 (내 경험, 대화형) | `chat.html` | 나: "화면 아래에서 올라오는 창 있잖아, 반쯤만 올라오는 거" → AI: (화면 가운데에 팝업을 띄워 옴) → 나: "아니 그게 아니라..." → 반복 → 결론 "**Bottom Sheet**라고 한 마디면 끝났을 일" + 재구성 주석 |
| 03 | 용어 ① | `term-mock.html` | Modal |
| 04 | 용어 ② | `term-mock.html` | Bottom Sheet |
| 05 | 용어 ③ | `term-mock.html` | Drawer |
| 06 | 용어 ④ | `term-mock.html` | Toast |
| 07 | 용어 ⑤ | `term-mock.html` | Tooltip |
| 08 | 한눈에 비교 (저장용 표) | `compare.html` | 열: 이름 / 어디서 나오나 / 뒤를 막나 / 저절로 사라지나 |
| 09 | 엔딩 (퀘스트 클리어 + 다음 예고 + CTA) | `ending.html` | 퀘스트 완료! / 저장해두고 AI한테 써먹어보세요 / 오늘 얻은 것 칩 5개 / NEXT QUEST #02 콘텐츠를 보여주는 방식 / 저장·팔로우 칩 |

- 서사 원칙: **게시물 하나 = 퀘스트 하나** (커버 = 퀘스트 수락, 본문 = 지점 탐험, 엔딩 = 클리어 + 다음 퀘스트 예고)
- 범용 기본 순서(design-system 7절): 커버 → 문제 제기 → 콘텐츠 ×5 → Before/After → 엔딩. 용어 시리즈는 QUEST #01부터 **Before/After 대신 '한눈에 비교'**를 씀. Before/After 템플릿(`before-after.html`)은 실제 AI 결과 스크린샷이 있을 때 쓰는 용도로 남아 있음

## 3. 색상(HEX), 폰트, 글자 크기·굵기 위계, 여백·그리드

모든 값은 `templates/assets/tokens.css`의 CSS 변수. 색·폰트를 바꿀 땐 이 파일만 고침.

### 3-1. 색상 (확정)
**종이 (배경)**
| 토큰 | HEX | 용도 |
|---|---|---|
| `--paper` | `#FFF9F0` | 기본 배경 (크림 도화지) |
| `--paper-warm` | `#FBEFDD` | 카드 안쪽, 프롬프트 박스, NEXT QUEST 카드 |
| `--paper-line` | `#EFE2CC` | 배경 점 모눈, 구분선, 표 점선 |

**잉크 (글자)**
| 토큰 | HEX | 용도 |
|---|---|---|
| `--ink` | `#3D3654` | 제목·본문 (순검정 대신 보라빛 남색) |
| `--ink-soft` | `#7A7291` | 부제, 설명, 푸터, "이렇게 설명했었다" 문장 |
| `--ink-faint` | `#B9B1C9` | 비활성, 자리표시, 점선 테두리 |

**기둥 색 (시리즈 구분의 핵심)**
| 기둥 | 파스텔(면) | 진한 색(작은 글자·선) | 별명 | `data-pillar` |
|---|---|---|---|---|
| 🎨 UI/UX | `--ui` `#F9B4C4` | `--ui-deep` `#D9637F` | 딸기우유 핑크 | `ui` |
| 🤖 AI | `--ai` `#A9D3F5` | `--ai-deep` `#3F82C0` | 소다 하늘색 | `ai` |
| 🧭 개발 일상 | `--dev` `#B4E3BE` | `--dev-deep` `#3E9960` | 새싹 민트 | `dev` |

- 런타임 변수 `--p` / `--p-deep`가 `data-pillar`에 따라 위 색으로 바뀜 (`series=` 값을 주면 crayon.js가 자동 설정)
- 파스텔은 **면**(배경 덩어리, 배지, 칩, 카드 테두리), 진한 색은 **작은 글자와 선**(QUEST 번호, 루트 점선, X 표시, 손글씨 키커)

**공용 포인트**
| 토큰 | HEX | 용도 |
|---|---|---|
| `--sun` / `--sun-deep` | `#FFE08A` / `#E0A722` | 형광펜, 별, 클리어 스탬프, 결론 카드 테두리 (기둥과 무관하게 공통) |
| `--lilac` | `#D2C2F5` | 보조 장식 (「만약에 UI」 구름·별 등) |
| `--peach` | `#FFC9A3` | 보조 장식, 목업 안 히어로 이미지 자리 |
| `--white` | `#FFFFFF` | 카드 안쪽, 목업 화면 |

- 목업 오버레이(scrim): `rgba(61, 54, 84, .5)`, 연하게는 `.32`
- **색 비율**: 종이 70% · 기둥 파스텔 20% · 잉크 8% · 노랑 포인트 2%
- **금지**: 파스텔 위 흰 글자, 연한 색 위 연한 글자. 파스텔 위 글자는 항상 `--ink`

### 3-2. 폰트 (확정, 모두 무료, 로컬 파일)
폰트 파일은 **`fonts/`**에 있고 `tokens.css`의 `@font-face`가 상대경로 `../../fonts/`로 불러옴 (웹폰트 CDN 필요 없음).

| 역할 | 변수 | 폰트 (fallback) | 파일 | 굵기 |
|---|---|---|---|---|
| Display (제목) | `--f-display` | Jua → Pretendard | `Jua-Regular.ttf` | 400 단일 |
| Hand (손글씨 메모) | `--f-hand` | Gaegu → Jua | `Gaegu-Regular.ttf`, `Gaegu-Bold.ttf` (`Gaegu-Light.ttf`도 있음, @font-face 미등록) | 700 주로 사용 |
| Body (본문) | `--f-body` | Pretendard → Noto Sans CJK KR | `Pretendard-{Regular,Medium,SemiBold,Bold,ExtraBold}.woff2` | 500 / 600 / 700 / 800 |
| Mono (번호·영문·코드) | `--f-mono` | JetBrains Mono → Pretendard | `JetBrainsMono-VariableFont_wght.ttf` | 500 / 600 / 800 |

- JetBrains Mono에는 한글이 없어서 한글은 Pretendard로 자동 대체됨
- Gaegu는 획이 가늘어서 **32px 미만 금지**, 짧은 메모에만 사용 (긴 본문 금지)
- 줄간격: 제목 1.2(`.display`는 1.22) / 본문 1.55. 자간: 제목 -0.01em
- `word-break: keep-all` (한국어 단어 중간 줄바꿈 금지)

### 3-3. 글자 크기·굵기 위계
**토큰 (tokens.css)**
| 토큰 | 값 | 용도 |
|---|---|---|
| `--t-hero` | 128px | 커버 메인 제목 |
| `--t-h1` | 84px | 카드 제목 |
| `--t-h2` | 56px | 소제목 |
| `--t-h3` | 40px | 작은 제목 |

## 6. 이미지 사용 규칙

- **사진 사용 안 함** (현재 확정된 모든 템플릿 기준). 비주얼은 CSS/SVG 손그림 장식 + 미니 목업
- **크레파스 질감은 장식에만**: SVG 필터 3종(`crayon.js`가 페이지에 주입)
  - `#wax`: 울퉁불퉁한 가장자리 + 왁스 입자 → 배경 덩어리, 배지 원, 칩, 형광펜, 카드 테두리
  - `#wax-stroke`: 가는 흔들림 + 끊기는 선 → 아이콘 선, 루트 점선, 스탬프 테두리, 목업 외곽
  - `#rough`: 흔들림만 → 프롬프트·설명 박스 점선 테두리
  - 구현 패턴: 글자가 든 요소에는 필터를 걸지 말고, `::before`/`::after` 배경 레이어에만 필터를 걸기 (`.card`, `.chip`, `.hl` 참고)
- **본문 글자에 질감·흔들림 필터 금지**
- 아이콘 세트(손그림 선, 100×100, `Crayon.icon(name)` 또는 `data-icon`): compass · map · pin · x · flag · key · star · arrow · scroll · magnifier · cloud · telescope · dice
- 고정 모티프: 커버 점선 루트 + X 표시 + "보물: ○○" / 본문 카드 오른쪽 위 진행 루트 점 5개 / 엔딩 노란 클리어 스탬프 / 배경 48px 점 모눈
- 장식은 한 장에 3~4개까지. 별·지도·나침반·스티커를 한 장에 잔뜩 넣지 않기
- 무거운 판타지 금지: 진한 갈색 양피지, 고딕 판타지 폰트 대신 밝은 크림 도화지
- 미니 목업 안 화면 내용은 회색 줄(`.ln`)과 블록으로 추상화. 실제 서비스 화면을 베끼지 않음
- 실제 AI 결과 스크린샷: Before/After 템플릿에서만 쓸 예정. 스크린샷 처리 규칙(크기, 테두리, 출처 표기)은 **미정**
- 외부 이미지·레퍼런스 디자인(예: 「이 디자인 왜 예쁨?」에 쓸 cosmos 등) 사용·출처 표기 규칙: **미정**
- 프로필 그리드 색 리듬: 같은 기둥 색이 가로로 붙지 않게 핑크 → 하늘 → 민트를 대각선으로 번갈아 배치

### 렌더링 방법
- `render.sh` 사용법 (헤드리스 Chrome, 기본 1080×1350):
  ```bash
  cd <프로젝트 루트>
  ./render.sh <템플릿.html> <출력.png> "<URL 쿼리>" [width] [height]
  # 예
  ./render.sh templates/cover.html out/cover.png "series=talk&no=2&kicker=...&title=...&pg=01%20%2F%2009"
  ```
  - 내부 옵션: `google-chrome --headless=new --force-device-scale-factor=1 --window-size=W,H --virtual-time-budget=5000 --screenshot`
- 텍스트는 모두 `data-field="이름"`이 붙어 있어 URL 쿼리로 바꿈 (HTML 허용: `<br>`, `<span class="hl">…</span>`, `<b>`)
- `series=talk|why|whatif|weekly|cando|log|silly` 하나로 색·배지·시리즈명·퀘스트 타입이 자동 전환. `no=`는 QUEST 번호, `pg=`는 페이지 표시
- 계정 아이디는 `handle=` 필드로 바꿀 수 있음 (현재 기본값 `@handle`)
- 게시물 일괄 빌드: `python3 posts/ui-talk-01/build.py [01 02 ...]` (새 편은 `posts/<slug>/build.py`를 복사해 문구만 교체)
- 미리보기 일괄 생성: `python3 build.py`
